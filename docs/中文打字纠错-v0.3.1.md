# 中文打字纠错

本版在本地解码器中增加一次相邻字母交换、或一次邻键替换的候选匹配。`ek` 可以匹配 `ke` 的词库前缀，推荐“可、可以、可是”；`ekshi` 可以匹配“可是”；QWERTY 下误触 `e` 的邻键 `w` 后输入 `kwshi`，也能推荐“可是”。短输入存在多个可能，不能唯一判断用户原本想写哪一个词。

纠错范围使用 QWERTY、QWERTZ、AZERTY 的字母位置计算邻键，跟随外观设置。候选仍通过系统词频和本机选词次数排序；原拼音的正常候选先显示，纠错候选使用独立的有限路径名额，避免正常词挤掉全部纠错词。词内比较最长 12 个字母，整段组合最多允许一次误触或错序，不处理任意拼写或多处错误。带隔音符的输入保持用户指定的边界，不应用打字纠错。

正在输入的原文保持不变。选中纠错词后，消费实际输入长度，使用正确的拼音记录用户词；未消费的拼音可以继续选词。普通输入不调用 API，不把逐键输入发给模型。

应用 → 输入与词库设置 → “中文打字纠错：字母错序与邻键误触”可以关闭此功能。这个开关独立于 zh/z 等音节模糊拼音开关。密码和原有不学习字段的规则继续生效。

代码入口：`TypingCorrections.java` 生成拼写变体，`ChineseEngine.java` 在词路径中保留并排列纠错候选，`Pinyin.java` 读取设置与布局。没有复制第三方输入法的代码。

设计参考：[Rime 拼写运算](https://github.com/rime/home/wiki/SpellingAlgebra)、[Rime ScriptTranslator](https://github.com/rime/librime/blob/master/src/rime/gear/script_translator.cc)。本项目的邻键与错序匹配由 Java 解码器独立实现。

验证工具：`tests/EngineChecks.java` 和 `tests/correction_smoke.py`。模拟器与真实手机的性能、候选覆盖不同，本版未做真机或帧率基准测试。原有齿轮按钮在练习页返回设置的导航问题未在本次改动中处理。
